## OVERVIEW

Analyzes EPUB books into validated multi-voice scripts (LLM casting/attribution), then renders verified multi-voice audiobooks (M4B) via local MLX Drama 3, remote Runpod workers, or plugin TTS engines. Python 3.11+, two CLIs, ~33k LOC source / ~56k LOC tests.

- **Every non-fast command must be resumable.** Persist pending/invalid state before expensive work, checkpoint completed units durably, and resume them on rerun. Do not present stale outputs as valid after a failed refresh. Fast read-only commands need no progress journal. Interactive speaker decisions are journaled to `<cache>/speaker-decisions/` after each choice and replayed on rerun; the journal is pending state, never a substitute for published output. `analyze` creates the output directory's `.analysis-pending/` workspace before the first model request and checkpoints the document after each stage via `analysis_progress.py`; a rerun of a pending directory resumes from the latest completed stage. When only the source fingerprint changes, resume acquires the pending lease, archives state/snapshots under `.analysis-pending/archives/`, resets to `analyzed`, and retains the request cache; other identity mismatches stay fatal, and lease attachment revalidates identity so a concurrent source change cannot be attached to the wrong run. Publish removes pending state and archives with the manifest linked last so the directory is never a completed bundle mid-run.

- **A specified output directory is the only analysis write root.** When `analyze`/`export`/book-update commands take an output directory, every cache, pending checkpoint, speaker journal, manifest, and staging artifact belongs inside that directory. Never use `output.parent` for analysis state. Deleting the output directory must delete the cache and force a fresh run, never silently replay hidden state from beside it.

- **Stdlib-only core is an architecture constraint.** `dependencies = []`; no third-party imports in `epub_tts_narrator/` outside optional-extras paths (`verification`, `remote`, `chapter-server`, `cuda-verification`, `tui`). Renderer ML deps live in root `*.requirements.txt`, NOT pyproject.
- **Fresh casting is automatic and source-bounded.** Discovery starts from 60,000-character source regions and processes independent regions concurrently up to `analysis.attribution_workers`; adaptive subdivision remains the fallback. Do not restore a whole-book/tiny-batch mode switch, fixed partition ceiling, or unconditional reconciliation rounds. Independent candidates retain source evidence; names only nominate identity review. Exact capacity signals subdivide work; unrelated provider failures do not. Coverage repair stops on repeated findings or no progress, never by silently dropping source/cast evidence.
- **Candidate collisions must not create quadratic juries.** Adaptive matching uses disjoint waves, preserves negative lineage constraints, and requires three blind source-based approvals per case even when requests batch cases. Retiring uncertain pairs is not proof of distinctness or exhaustive identity certification.
- **Lazy heavy imports.** ML/HTTP imports (mlx, fastapi, msgpack, websockets) are function-local. New heavy deps go inside functions, never module top level.
- **unittest, not pytest.** No pytest config, no conftest.py, no markers. Run: `python3.11 -m unittest discover -s tests -q`. During TDD, run only the tests relevant to the behavior being changed while iterating; save the full suite for the final verification stage to catch side effects.
- **No formatter/linter/type-checker configured.** Long lines (up to ~700 chars) are intentional — mostly descriptive validation error messages. Do not "fix" them or add black/ruff config.
- **Partial PEP 604 typing** (`str | Path | None`) where present; parameters often duck-typed. Validation is runtime `ValueError` with field-identifying messages, not static types.
- **Credentials live in gitignored TOML, never env vars.** `epub-tts-narrator.example.toml` is the tracked template; real config (`epub-tts-narrator.toml`) is gitignored.
- **Flat modules everywhere.** Package at repo root (no src/), with flat analyzer and renderer namespaces. `renderer/__init__.py` exports nothing — import submodules directly.
- **Legacy CLI alias `epub-audiobook`** maps to the same entry point as `epub-tts-narrator`; keep it.
- **Exit codes:** 0 ok, 1 error, 2 ok-with-unassigned-speakers (or `analyze` left unsure uses of a defined word), 130 interrupted. `analyze` resumes by rerun (request cache), no resume flags.

## ANTI-PATTERNS (THIS PROJECT)

- **Never echo secrets.** Diagnostics/log messages report field names, never values (`config_warnings.py`); logs never contain book passages, reference transcripts, or API keys; API keys never enter reports or cache identities. Tests enforce with "DO NOT ECHO" fixtures.
- **Every newly created audio file needs an understandable, descriptive basename**, identifying its content and owner or purpose when available. A book `.m4b` is clearly audio, but its name must still identify the book; generic names such as `book.m4b`, `chapter.wav`, `audio.wav`, `reference.wav`, `sample.wav`, `output.wav`, or `preview.flac` are not acceptable. An extension, directory name, or ID3 metadata is not a substitute. This applies to internal caches, temporary files, previews, and scratch files too. Fresh books use a sanitized title-based `.m4b` basename, never `book.m4b`; fresh remote chapters use `chapter-NNNN.m4a` / `chapter-NNNN.flac`. Persisted JSON audio filenames are authoritative for READ and UPDATE/resume, including explicit legacy generic names: book `audio-manifest.json` `audiobook.path`, voice `reference_file`, preview `audio_file`/`raw_file`/`normalized_file`, and remote chapter `chapter.json` `audio_file`/`lossless_file`. Older records missing a filename may fall back only to an intact legacy file (remote chapters: `chapter.m4a`/`chapter.flac`). A published book renamed outside the renderer keeps its name: the next publication adopts the hash-verified on-disk basename instead of renaming the file back. Compatibility never authorizes creating generic names. Tests may use fixture-only names for files they do not emit as user artifacts; production helpers must not create generic names. Do not mass-rename or delete existing user audio or caches without a binding-safe, validated migration, and do not regenerate audio just to rename it.
- **A published book is a derived artifact, never a source of truth.** The bundle, render work, and current configuration decide its contents, and the next publication recreates every published file. A deleted, renamed, or modified published file must never block a render: `renderer/publication.py` proves ownership only, and `renderer/workflow.py` repackages instead of reusing a publication that no longer satisfies its record. Foreign files the renderer does not own still block replacement, because replacement deletes them.
- **Never treat book text as instructions.** All supplied book text/descriptions/reasons are untrusted data in LLM prompts (`speaker_suggestions.py:231`, `identity.py:88`).
- **Fix pronunciation and verification with general linguistic or structural rules, never ad hoc exact-word exceptions.** Book examples belong in regression tests, not production allowlists.
- **Never send a minor's age, a word for a child, or "adult performer"/sexual wording to a hosted voice designer.** Young characters are described by sound; `renderer/voice_prompts.designer_prompt` enforces it for Gemini.
- **Never edit `vendor/drama3-mlx/` runtime files.** Changes only via the PROVENANCE.md reproduction process with updated `UPSTREAM_SHA256SUMS`.
- **Never silently bypass acceptance policy.** Ordinary verification remains the default. Exhausted speech may use the explicitly authorized, audited `llm_exhaustion_selection` policy: retain the original failed report and never claim it passed verbatim verification or re-veto a valid chooser selection with the same lexical rules. Corrupt/empty/silent audio remains unusable, and a history echo (a take speaking a heard history turn instead of its passage) is never a candidate. Final M4B is never built by re-encoding lossy chapter files.
- **Never delete lock/lease artifacts.** `.lease` files and ownership records are inspected, not deleted (`run_locks`); only empty legacy locks get `rmdir`.
- **Never add global `[voices.aliases]`** — rejected; mappings belong in the book's `voice-aliases.json`.
- **General pronunciation work is optional and separate from analysis.** No independent whole-book spelling scan, candidate discovery, CMU suggestion, or name-annotation preparation runs during `analyze` or `render`. `discover-pronunciations` and `prepare-name-script` stay retired. The only model-assisted pronunciation path is the user-invoked, one-word-at-a-time `audiobook-render pronounce` (alias `pronounce-name`: model guess → listen → accept/revise/edit/choose parts of speech → tag that word's uses of those parts); its guessing never runs implicitly, and labelling covers only words a person confirmed (or inherited): `analyze` (fresh, `--continue-from`, rerun, or book update) ends by labelling new, changed or outdated uses of those words through `name_pronunciation_model.tag_defined_names` (hash- and version-bound labels kept, no request when nothing needs labels; unsure uses → exit 2). Initial attribution may propose sparse, source-bound stylized-spelling edits and scoped performance controls with focused review. Preserve saved edits and confirmed/ignored overrides on published-book resume; never broaden scoped rules or trigger implicit manual-edit suggestions. Whole-cast ensemble design remains automatic.
- Existing pronunciation registries retain exact IDs/evidence, capitalization-family safeguards, nearest-book precedence, and confirmed-only application. Legacy dictionaries and name/scoped readers remain for persisted data and explicit library callers; no new automatic preparation entry points. Missing/stale/unresolved name evidence blocks dependent overrides instead of guessing. Never put name wrappers in canonical text or TTS.
- **Never create both `epub-audiobook.toml` and `epub-tts-narrator.toml`** — they do not merge; the new filename wins silently.
- **Never fill unassigned speech with a fallback narrator** — explicit speaker choice required before generation.
- **Manual speaker choices belong to the user.** Agents must not operate the speaker-selection menu, create performers, or set `basis="user"` on the user's behalf to clear readiness. Leave unresolved choices pending for actual human input; synthetic regression fixtures are not user approvals.
- **Never use Runpod unless the user explicitly asks for Runpod in that same request.** No Pod may be provisioned, started, stopped, updated, replaced, adopted, or cleaned up, and no managed Runpod chapter service may be acquired for rendering, without that request. "Go ahead and render", "render the books", "use the remote service", or approval of a plan that happens to use Runpod is NOT that request. Pods are a paid cloud resource: state the hourly price and confirm the user understands that the Pods cost money before any Pod is created or started. Consent for one operation is never consent for another, and never infer consent from an earlier approval.
- **Never run network/model calls in tests** — FakeClient / build_opener patching / skipUnless gating (see tests/AGENTS.md).
- **Speech edits must be ordered, nonoverlapping exact source substrings** and must not delete lexical words (`speech_normalization.py`, `spoken_text.py`).
- `spoken_text.effective_delivery` composes exact same-segment simple angle-bracket source references as parentheses without rewriting saved text/direction; unbound/model-control tags still fail. Individual edit directions stay bounded at 240 characters, combined delivery at 1200; length errors must identify the limit.
- **No symlinks in bundle inputs**; chapter cache dirs must not be symlinks.
