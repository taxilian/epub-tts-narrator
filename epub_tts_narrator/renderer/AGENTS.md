# RENDERER PACKAGE

## OVERVIEW

Flat renderer subpackage plus `ENGINE_NOTES.md`.
Resumable, quality-gated audiobook rendering, assembly, casting, and remote execution.

Keep this file current: when modules, entry points, or conventions change, update it in the same commit.

## ENTRY

`audiobook-render` maps to `renderer/cli.py:main`; `python -m epub_tts_narrator.renderer` also works.
Subcommands: `plan`, `cache-report`, `render`, `assemble`, `refresh-metadata`, `cleanup`, `history-echoes`, `voices`, `create-voices`, `import-voice`.
More commands: `cast`, `voice-aliases`, `pronounce-name`, `doctor`, `serve`, `serve-chapters`, `runpod` (bootstrap/update/encode/status/stop/progress/cleanup).
Performance commands: `prepare-performance`, `compare-performance`; default rendering also consumes validated inline attribution controls without a separate preparation pass.
Pronunciation command: `pronunciations` with review/list/set/ignore/reset/play/migrate actions; discovery and automatic CMU/name-hint generation are retired. Manual respellings stay literal, manual CMU stays explicit, and no analysis provider or network is required. Default `review` opens the listening queue without preparing proposals, estimates, or audio (`pronunciation_review_queue.py`, state sidecar in `pronunciation_review_state.py`): count-only menu, `S [N]` start, isolated pairs with interruptible gaps, receipt-bound acceptance, and last-five resume. Ordinary queue walks skip saved machine proposals; explicit `S N` or numbered playback plus confirmation can accept their exact saved phones. Playback uses saved character voices only.
Name command: `pronounce-name BOOK NAME` (`name_pronunciation_tool.py`) is the one user-invoked, model-assisted pronunciation path: model guess (or `--phonemes`, draft, own/inherited choice) → `PronunciationReviewSession.audition_sentence` test sentence with the name, possessive and (when used) plural → `A`/`I text`/`N`/`E phonemes`/`B`/`P`/`Q`, drafts checkpointed → batched model tagging of real uses (homonyms `other`, `unsure` asked). Without NAME it tags every defined/inherited name still untagged here. `name_pronunciation_tags.py` binds tagged spans in `make_plan` via `merge_row_pronunciations(matches=...)` (tags win overlaps; frozen as `_tagged_name_snapshot` in `_preflight`); untagged/unsure uses block planning.
Ordinary capitalization variants share review and confirmed runtime choices via `pronunciation_groups.py`; preserve exact v1 registry IDs, source offsets, and preview receipts. Queue state and drafts resolve group variants, while conflicting explicit choices/drafts stay visible until resolved and known capitonyms/short initialisms remain separate.
`serve` exposes a Fish-compatible `/v1/tts` service through `server.py`.
`serve-chapters` runs the resumable job server in `chapter_server.py`.
Normal flow: plan, cast or bind voices, render chapters, verify, assemble, publish.

## STRUCTURE

1. Orchestration/config: `workflow.py`, `cli.py`, `config.py`, `book_context.py`, `book_aliases.py`, `common.py`, diagnostics, locks, progress, payload-free render metrics, recovery identity.
2. Speech verification/recovery: `quality.py`, `verification.py`, `speech_resolver.py`, `verification_prompts.py`, `speech_identity.py`, `ordinal_words.py`, coverage, cache, recovery, text, phonetic, ASR, retry modules.
3. Chapter/distributed pipeline: `bundle.py`, `chapter_jobs.py`, `chapter_sessions.py`, `chapter_protocol.py`, `chapter_records.py`, `chapter_executor.py`, `chapter_client.py`, servers, cache, storage, verification, pool.
4. Casting/voice design: `casting.py`, `casting_batch.py`, `audition.py`, `voices.py`, `voice_design.py`, provider design modules, prompts, bindings, samples, letter names.
5. TTS engines: `engines.py` (`HistorySynthesis`), `fish_http.py`, `mlx_audio_engine.py`, `fish_speech_engine.py` (Runpod CUDA), `drama3_batch.py` + `drama3_batch_scheduler.py` (batched CUDA decoding), `request_sampling.py`, local runtime, model setup, Drama 3 model/design/sampling modules.
6. Assembly/publication: `assembly.py`, `publication.py`, `book_output.py`, `book_artwork.py`, `book_metadata.py`, `refresh_metadata.py`, `cleanup.py`, paragraphs, paragraph recovery, loudness, pacing.
7. Runpod deployment: `runpod.py`, `runpod_api.py`, `runpod_gpu.py`, `runpod_config.py`, `runpod_progress.py`.

## CONVENTIONS

- Renderer imports are direct submodule imports; `__init__.py` exports nothing.
- `voice_prompts.py` validates descriptions without adding age, actor, or context prefixes. The LLM authors relevant portrayal context once in its prose. Recognize historical application wrappers only for stripping old drafts and comparing recovery provenance; never rewrite saved requests or selected voices merely to remove a wrapper.
- `audition.py` lays out cast rows in adaptive columns; `E` edits without generation, `D` links a source row to a target through book-local aliases, and regeneration also edits speech traits. `CastingSession.share_voice` never merges characters or deletes recordings. Description/script drafts belong to the canonical reference; manual traits belong to the logical voice and remain distinct across audio aliases.
- Casting edit prompts stage all fields before saving. `B`, `/cancel`, or Ctrl-C during description/script/trait entry discards that edit and returns to the menu without generation; Ctrl-C outside edit entry retains its normal interruption behavior.
- Gemini bulk casting uses `casting_batch.py`, not the chapter render pool. Deduplicate canonical IDs before admission; hold the series lease until started jobs and hosted-voice cleanup drain. Model setup and cleanup sweeps run before workers; private jobs inherit cleanup-attempt state, and verifier construction/calls/close stay on one thread. Ordinary failures preserve sibling success; fatal verification/setup failures and interruption stop admission. Bulk regeneration invalidates all targets before the first generation, leaving unstarted targets pending.
- Casting verifier affinity belongs to the entire Gemini-capable `CastingSession`, not a batch: single `GG`, bulk work, and temporary designer overrides reuse the same verifier thread and lazy global model cache until session close. Allocate at most `gemini_concurrency` private workers and reuse a slot only after its previous job completes; never copy the whole book once per cast member up front.
- `speech_traits.py` reads/writes identity-checked `voice-traits.json` overrides, nearest book first. Empty values deliberately clear traits and shadow ancestors. `_preflight` snapshots effective overrides for local/remote recovery; only affected chunk conditioning changes cache identity. Pronunciation previews and comparison snapshots preserve effective traits. Parent lookups check manifest/cast metadata without reparsing chapter scripts on menu redraw. Never edit checksum-bound cast files through the casting UI.
- Expressive plans and segment `performance_controls` bind approved spoken text, never canonical source replacements or voice identity. Consume inline controls in default rendering too; merge exact duplicates with optional external records and reject conflicting overlaps. Compile only validated structured metadata; raw book markup stays untrusted. Keep legacy request/cache identities unchanged when no controls are supplied.
- Delivery/emotion spans may start/end inside one segment; scoped ends restore baseline voice/passage delivery. Vocalizations/pauses are point events, not invented spoken words. Project controls across chunks and paragraph turns, assigning boundary events exactly once. Apply normalization-derived hints once and confirmed manual pronunciation controls last. Unsupported structured-control backends fail explicitly; control syntax never proves acoustic adherence.
- `prepare_synthesis` is shared by adapters and speech cache identity; edge trimming projects controls by retained code-point indices. Text-only rewrite/split recovery is disabled for expressive leaves until it can preserve those bindings; fallback to original paragraph turns retains each turn's controls.
- `compare-performance` freezes selected references and source in its own directory. Its frozen voice store cannot create voices, and `_preflight` must use the supplied store directly rather than derive aliases again. Both modes use one engine instance, independent verified caches, source timing, and a local HTML listening report.
- Intentional pauses excuse only measured silence at their exact ASR word boundary, within the requested bound. Inline vocal events are excluded from lexical expectations but are not acoustically certified. Neither event metadata nor text review can authorize silent or corrupt audio.
- Censorship defaults off in global `[censorship]`; `render`/`assemble --censor` and `--no-censor` override it. Match whole original-source words and project approved spellings; never infer target indices from nonexact ASR word counts. Apply validated frame masks after original edge trimming, separately per simultaneous lane before mixing. Bind policy only to composition/publication identity, never speech acceptance or voice identity.
- `assemble --chapters-only` can rebuild censorship from original accepted clips without TTS. Missing timing may lazily load MLX Whisper for cached, known-text attention alignment. Require independent ASR complete lexical coverage first; retained missing/different words or uncertain boundaries stop with originals intact. Reject target durations below 20 ms. Preserve actual frame count, full original verification, and per-lane censorship audits in sync. Downloaded remote chapter audio alone cannot rebuild a changed policy locally.
- Heavy ML and HTTP imports stay inside functions, never at module scope.
- Chapter continuity is mandatory synthesis behavior (no `render.continuity` setting). Fixed reference audio/transcript never change; history is Fish's first + latest policy applied per voice: `ChapterContinuity.takes(speakers)` selects only accepted takes whose script voice ids ⊆ the request's (`request_speakers`: chunk voice ids, or a simultaneous lane's performer — never asset hashes, so a narrator linked to a character's recording keeps separate history; take identity is unchanged) (first pinnable take pinned; heading-only takes never pin) — no other character's audio enters a prompt. `continuity.compose` renumbers speaker tags per request (request voices first, history-only voices appended, ≤16); `candidates` follows Fish's overflow order (drop latest, then pinned) and every engine records `history_turns`. Engines subclass `engines.HistorySynthesis`, implement only `_generate_wire`, and return `generated_codes`; `continuity_codes.persist` writes hash-named `*.codes.json` in the take loop before normalization. Rejected takes never advance history; joins/repairs/best-effort/simultaneous lanes leave it unchanged; chapters start fresh; silent controls do not reset. Identity binds history. `[render] history_reuse` (local only, not in `SAFE_RENDER_KEYS` or any identity) decides what a changed take does to the rest of its chapter: `"tolerant"` (default) keeps a later take when `continuity.without_history` of its identity is unchanged — `SpeechCache.find_earlier_history` looks it up by chunk ID plus that identity (position index built from accepted records), excludes audio the chapter already holds (`ChapterContinuity.accepted_audio`), keeps only `ordinarily_verified` takes (never a best-effort exhaustion choice; `matches` applies the same rule when history differs), checks engine compatibility, and never publishes an alias under the new identity; `accept(tolerate_history=True)` then requires its codes to match the history in its own request and counts `drifted`. Restore (`matches(tolerate_history=)`) and `cache-report` (`history_changed_hits`) follow the same setting; `"strict"` replays exactly, so a changed take makes the rest of that voice's chapter stale. Missing/corrupt codes fail closed and are never rebuilt from WAV. `RenderPool` submits all TTS takes under one default lane owner, giving global FIFO submission order; `_Slots` claims the first free worker in configuration order at dequeue (`ResourceLane.submit(reserve=…)`), and legacy callers use a FIFO waiter queue. There is no chapter-to-worker affinity or load tracking. Waiting takes hold no lane thread or worker slot, while per-request history and references can continue on any worker. Recognition is a separate worker pool: the controller's own recognition thread (`_recognition_runtime`, never the synthesis model thread) plus `serve` workers whose `roles` include `recognition`; `_SerializedVerifier` sends only `RECOGNITION_CALLS` (`transcribe`, `transcribe_reference`, `corroborate_reference`) to `RenderPool._recognize`, which uses one FIFO lane and reserves the first free recognition slot at dequeue. `render_resources.run_recognition` keeps the original owner scope separately from the FIFO queue owner for nested verification. `recognition_workers.RemoteRecognizer.verify` requires the worker's path-free recognizer identity (`comparable_identity`) to equal the controller's at `wrap_verifier`, and every response echoes that identity's digest; saved verification identity stays the controller's. `recognized_by` provenance appears only when remote recognizers exist. Drama 3 always renders through a pool (one-slot local by default) with the pipeline scheduler so chapters overlap on one model. Runpod `runpod.inference_replicas` (1-4) loads independent single-request Drama 3 copies on ports 8080, 8090-8092 (`runpod_config.inference_ports`/`inference_workers`), one render-pool worker each; `deploy/runpod/worker.py` checks GPU memory per copy, starts all copies (optionally under a private MPS daemon, `inference_mps`), and smoke-tests every copy. `fish_http` speaks only `serve` protocol `audiobook-history-wav-v2` (history in, MessagePack WAV+codes out, `/health` checked once); stock Fish/SGLang/hosted APIs are rejected. Sampling and seed are the coordinator's: `server._sampling` requires all of them and the response echoes them; the client rejects a take whose echo differs. Runpod runs `serve` with `fish_speech_cuda` inside Fish's environment.
- Confirmed pronunciations apply in legacy and expressive modes. `_preflight` freezes effective decisions per invocation; local/remote paragraph recovery uses that snapshot and the next run reloads ancestors. Bind only affected source-mapped slices; preserve canonical text and unchanged speech identities. Override stale normalization-derived hints only on the corrected word. Reject ambiguous multiword mappings and conflicting explicit controls. `pronunciation_review` caches isolated FLAC listening previews; these are not accepted audiobook speech or voice references. Drafts survive review exits but never affect book rendering before confirmation. Saved legacy proposals stay pending until explicitly selected; numbered playback uses their exact phones without generating replacements. C requires the same ready preview and hash-bound playback receipt with the current saved voice; manual CLI set with either respelling or phonemes is an explicit direct override. The listening queue (`pronunciation_review_queue.py`, sidecar in `pronunciation_review_state.py`) auto-accepts only uninterrupted isolated pairs verified by that receipt; `terminal.play_sample` returns completion vs interruption and raises on real player failure (`AudioPlayer.poll`/`wait` surface nonzero exits), and `terminal.wait_key` reports gap keys. Isolated previews construct the word-only control directly (no source-normalization mapping) with a cache identity and purpose distinct from excerpt previews; excerpt previews omit, on a row copy, only analyzer edits overlapping an exact occurrence of the target word and never mutate canonical rows. Queue resume is saved before each word's preview work; interruption shows the last five words with indices and resumes at the first of them. Reopen (`O`) only marks sidecar entries (local and inherited) for re-listening — the registry stays byte-identical until a pair is accepted. Never claim phoneme syntax or ASR proves acoustic pronunciation.
- Use the separate Python 3.12 uv environment and root `renderer.requirements.txt`.
- Pronunciation review (`pronunciations`) is manual-only; `pronounce-name` is the sole model-assisted exception and runs only for the name a person names (or names already defined/inherited). In `pronunciations`, never create proposers, discover candidates, generate CMU suggestions/estimates, convert readable hints through a model, or prepare name annotations. `set --say-as` and `set --phonemes` directly save explicit choices; `play` auditions without saving. Interactive `E` saves a literal respelling draft, and explicit playback alone generates previews. Legacy estimate files and saved proposals are inert except that an explicitly selected saved proposal can still be auditioned/confirmed.
- Default pronunciation rows apply `pronunciation_dictionary.review_candidates` after draft/case-family decoration. Dictionary-known automatic pending rows are hidden non-destructively; cast names, drafts/manual intent/conflicts and explicit `--word` selections remain reviewable. Cache the frozen session's cast-name word set rather than rescan book text per menu redraw. This offline filtering is not candidate discovery and never creates proposals or choices.
- Scoped review uses `scope` hashes below the preview directory, isolating drafts/queue state and receipts for identical spellings. Name scopes resolve numeric labels to stable character identities; Special scopes exclude marked/unresolved names. `_preflight` freezes `_name_pronunciation_snapshot`; source matches feed existing controls via `merge_row_pronunciations(matches=...)`, not marker text or new chunk fields. Preserve normal source mapping/normalization conflict guards and acceptance policy. Scoped reads/migrations never rewrite legacy registries; migrations apply to their legacy family and own/older books only.
- FFmpeg and FFprobe are required; paths come from TOML configuration.
- `engines.py:create_engine` supports entry-point groups `epub_tts_narrator.tts` and legacy `audiobook_renderer.tts`.
- The default engine is `drama3_mlx`; unknown or ambiguous engines raise, with no silent fallback.
- Engine plugins provide typed `identity` and `capabilities` dictionaries.
- Required identity fields: `engine`, `model`.
- Capability fields: `voice_design`, `reference_voice`, `preset_voice`, `delivery_control`.

## ANTI-PATTERNS

- Do not add renderer dependencies to the analyzer environment or import heavy packages at module load.
- Do not use the Runpod SDK; `runpod.py` calls the Runpod REST API through `urllib`.
- Do not enable HTTP redirects in `chapter_client.py`; configure a direct URL.
- Do not accept remote artifacts before size and SHA-256 verification, then atomic rename.
- Do not transfer reference WAVs unless they are mono, 16-bit audio.
- Do not trust compressed voice transfers until their decoded PCM hashes match.
- Do not run `audition.py` regenerate-all casually: it replaces voices in the shared series library and does not ask for confirmation.
- Do not replace immutable audition history or voice assets in place.

## NOTES

- `progress.TerminalBoard`/`live_board` own the interactive render display: `render()` swaps `print` for the board's print-compatible `log` on a TTY; each `ChapterProgress` keeps one row (`_row`), the board adds the `sched` footer, erases/redraws exactly the drawn rows around every log line, and never calls back into producers (no lock inversion). Non-TTY and custom notify keep plain output. Automatic `chapter_concurrency` is `min(16, max(4, slots))` (per-voice queues keep each chapter supplied).
- `render_metrics.py` owns payload-free bounded stage metrics: closed `STAGES` set, fixed histogram buckets, completed/failed/cancelled outcome counters. Instrument resource entry/exit only; snapshots never carry text, URLs, keys, or user labels, and `gpu_telemetry` is a constant until a collector exists.
- `common.py` has only 51 lines but 33 internal consumers; treat changes as high blast radius.
- `render_lanes.py` owns bounded cancellable resource lanes: fixed declared worker pools, one global submission-ordered queue for every lane type, earliest-eligible reservation without same-resource reordering, FIFO capacity waiters, submit-time context copies, stop checks at dequeue, `LaneFull` backpressure for nonblocking submitters, and same-lane submit/close guards. Owner metadata remains only for scoped cancellation and nested routing. Lanes never execute model work; callables keep delegating to `LocalRuntime`.
- `render_pipeline.py` owns the shared logical clip scheduler: globally bounded transactions dispatched in global submission order, FIFO pending-submit waiters, per-owner cancel/retire only, source-ordered collect; coordinators never run on it. A failed transaction closes its owner's admission inside the worker's locked section (queued siblings popped before any pump, cancelled after), submits to a closed owner raise `AdmissionClosed` until `retire_owner` reopens a fresh generation. `render_pipeline_config.py` owns validated `render_pool` scheduler controls (default `pipeline`, `0` = automatic) and their effective values; they never enter `RENDER_CONTRACT`, `SAFE_RENDER_KEYS`, or any render identity, and pipeline remote projection drops the legacy `4*C` inflight override in favor of automatic admission.
- `render_chapter_flow.py` owns chapter coordination on that scheduler: `collect_chapter` (share-bounded submissions, source-ordered results, fail-fast drain) collects via per-future done-callbacks + a Condition — never `concurrent.futures.wait`, which CPython 3.11 never wakes for scheduler-cancelled raw futures; cancelled drain outcomes never mask the original failure. `run_units` bounds book-level coordinators and closes run admission on first failure. Pipeline pools report one `max_inflight` everywhere (effective 16 local / `min(256, max(64, 16*slots))` remote; legacy keeps slots+1 and builds no runtime), and chapter_jobs passes `(job_id, epoch)` as `scheduler_owner` only to executors that name the parameter.
- `render_backlog.py` owns attempt-scoped untranscribed-audio backpressure: `BacklogBudget` (exact pending count from `synthesis_backlog`, soft byte high-water with half-mark resume, monotonic `peak_pending_count`/`peak_materialized_bytes` gauges that survive release), tickets released at primary-ASR return or earlier take exit, saved-unverified/joined audio adopting at the `validate_audio` boundary without spending generation budget; recovery assemblies reserve nothing pre-generation (children reserve; the joined take adopts). `render_backlog_context.py` owns the context-side half — `begin_attempt_ticket` acquisition, `AttemptTicket` transfer, `current_ticket` — re-exported unchanged by `render_backlog`.
- `render_schedule_status.py` owns read-only scheduling diagnostics: one passively registered runtime slot (`register_runtime`/`clear_runtime`, wired by `chapter_executor` only after an engine already exists), conservative numeric snapshots of scheduler mode/capacity basis, logical gauges, backlog peaks, and per-stage queued/active; `chapter_jobs.scheduling_status` wraps it for `GET /v1/jobs` (additive `scheduling` block, advertised as `scheduling_status: 1`), `progress.py` renders a `sched` line segment, and `runpod_progress.py` projects fixed numeric keys only. Observing never initializes models, opens sessions, renews leases, starts inference, or grows registries; unknown executors/servers report nothing rather than invented values.
- `render_resources.py` owns the pipeline lane set owned by one `RenderPool` (legacy mode builds no runtime): TTS lane (one worker per declared slot), two-worker preparation lane, single recognition lane, `review_concurrency` HTTP leaves plus a `2*review_concurrency` coordination lane; every pending bound follows the same effective `max_inflight` the logical scheduler admits. `ResourceLane.run` blocks for pending capacity (stop/closed wake) instead of raising `LaneFull`, so saturated lanes backpressure runners and a submitted function never runs twice. Verification leaves submit from a fresh `Context` so a started take drains after owner loss; queued synthesis still stops at dequeue. `render_resource_context.py` owns `resource_scope`/`current_resources`/`current_owner` and the leaf helpers that call directly when no scope is active. `LocalRuntime` model-affine execution runs inside `suppress_resource_routing`: nested leaves direct-call on the model thread (scope values stay readable for tickets/metrics) because lanes block on that thread and a nested re-route would deadlock its own lane; ordinary coordination parents keep routing.
- `workflow.py` is about 2,317 lines and the largest maintenance risk; keep changes local.
- `workflow.render()` restores completed chapters when the context hash matches.
- **Audio writer seam:** Every newly written audio file, including internal/cache/temp/preview/scratch audio, must have an understandable basename identifying its content and owner or purpose when available. Preserve useful chapter, character, source, role, or sequence context for debugging. Extensions, directories, and ID3 metadata do not make generic basenames acceptable. Fresh remote exports use `chapter-NNNN.m4a` / `chapter-NNNN.flac`. Persisted JSON filenames are authoritative for READ and UPDATE/resume, including legacy generic names: book `audiobook.path`, voice `reference_file`, preview `audio_file`/`raw_file`/`normalized_file`, and chapter `audio_file`/`lossless_file`; missing legacy chapter fields fall back to `chapter.m4a`/`chapter.flac`. Backward compatibility never authorizes new generic names. Do not mass-rename/delete existing audio or caches without a binding-safe validated migration, or regenerate solely to rename.
- Serial updates: chunk IDs and the chapter context's `source_fingerprint` use `bundle.chunk_identity_fingerprint(manifest)` (`provenance.chunk_identity_source_fingerprint`, else the manifest fingerprint), so appended chapters never change earlier chapters' plans and edited chapters keep unchanged lines' chunk IDs (the analyzer keeps their block/segment IDs). When only `total_chapters` differs, `_total_restore_context` restores under the saved total and `_retag_chapter_total`/`reencode_chapter(total_chapters=…)` re-encodes verified PCM for the new track tag (render and assemble). `book_metadata.accepted_source_epubs` accepts the original EPUB (book ID) or the latest `provenance.book_updates[-1].epub_sha256`; never change `source.book` on update.
- It writes `status.json` and `plan.json` under `work_dir`, with directory locks from `run_locks.acquire_directory_lock`.
- See `ENGINE_NOTES.md` for engine-specific details.
- See root `RENDERER.md` for renderer configuration and operation.
- See root `REMOTE_RENDERING.md` for distributed rendering contracts.
- Chapter execution requires a connected client. Scheduling and event cursors are current-run only; ACK or disconnect discards run rows after accepted work drains. Persist validated audio/cache manifests, never past-run receipts or scheduling permissions.
- `chapter_client.py` publishes verified remote M4A symlinks under `WORK/chapter-links` before ACK and backfills them on cache reuse; never create partial links inside the final publication directory.
